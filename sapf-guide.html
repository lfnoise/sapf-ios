sapf Guide

sapf, “sound as pure form”, is a language for creating and transforming sound. This guide explains the idea behind it, how to use the app, and the language itself.

1. The idea

In sapf, a sound is a value. You build it by combining functions, the way you would build a number with arithmetic, and then you listen to it. A short program can describe a rich, changing sound.

Four ideas make that possible:

  • Postfix, on a stack. Values go onto a stack and functions take their arguments from it, as in FORTH or Joy. You write 2 3 + rather than 2 + 3, and a program reads left to right as a pipeline: start with a value, then transform it, step by step.
  • Lazy, possibly infinite sequences. Audio signals and streams of control values are lists that are computed only as they're needed, so they can go on forever.
  • Automatic mapping. As in APL, functions apply themselves across lists. Give an oscillator a list of two frequencies and you get two oscillators, which play in stereo. You almost never write a loop.
  • Immutable values. Nearly nothing can be changed once made, so sounds can be computed on several threads at once safely.

2. Your first sound

TapClick Run beside this example to hear a sine wave.

800 0 sinosc .3 * play

To stop a sound, use the ■ Stop button that appears under its Run button while it plays. That stops just that sound. If you ran the example more than once, each press stops one, the most recent first.

The ■ Stop button in the toolbar (or ⌘.) stops every sound at once.

Sounds keep playing until you stop them, even when you go on to the next example.

Read it left to right:

  1. 800 and 0 go onto the stack: a frequency of 800 Hz and a starting phase of 0.
  2. sinosc takes them and leaves a sine wave signal on the stack.
  3. .3 * multiplies the signal by 0.3, making it quieter.
  4. play sends it to the speakers.

Now something that moves. Here the frequency of the sine wave is itself a signal: a slow sawtooth wave sweeping it between 300 and 700 Hz.

.5 0 lfsaw 200 * 500 + 0 sinosc .2 * play

And a classic: “analog bubbles”, from SuperCollider. The list [8 7.23] makes two of everything, one for each speaker.

.4 0 lfsaw 2 * [8 7.23] 0 lfsaw .25 * 5/3 + + ohz 0 sinosc .04 * .2 0 4 combn play

3. Using the app

The window

The editor holds your code. Next to it, or below it on a narrow screen, are the console and three scopes:

  • The console shows the code you ran (after sapf>), anything it printed, and then what’s left on the stack.
  • Scope shows the sound as it plays, like an oscilloscope. Pinch to zoom; double-tap to go back.Scroll or pinch to zoom; double-click to go back.
  • Spectrum shows how loud each frequency is, and Sonogram shows the spectrum over time.

Dragging on any of the scopes controls mousex and mousey, so you can play a sound with your fingermouse or finger:

300 1000 xmousex 0 sinosc .2 * play

Drag the divider between the editor and the panel to give either more room. On a small screen, the panel shows one of these at a time; choose with the buttons at its top.

Running code

Code runs a block at a time. A block is a run of lines with no blank line between them. Blank lines inside brackets don’t end a block, so a long expression in brackets can be spread over several lines.

  • Put the cursor in a block and press Run (▶ in the toolbar), or ⌘Return.
  • Or use the ▶ in the margin beside each block. Touch and holdRight-click it to select or copy the block instead.
  • If text is selected, Run runs just the selection. Shift-Return runs the current line.
  • While a block’s sound is playing, a red ■ appears in the margin under its ▶. It stops the sound from that block’s most recent run, and nothing else. If you ran the block several times, press it again to stop the run before that, and so on: last started, first stopped.
  • Stop (■ in the toolbar), ⌘., or the word stop stops every sound.

Each run starts with the stack left by the one before. Clear Stack in the More menu (⋯) empties it, as does the word clear.

Help on any word

TapClick a word in the editor to see its help. For a variable you’ve defined, you see its value. Turn this off with Help on Tap in the More menu.

Documents

The Documents menu (the folder button, or the document’s name at the top) lists your documents:

  • Scratch, for trying things out.
  • Examples: hundreds of example sounds, from simple to elaborate.
  • Builtin Function Examples: short examples of the built-in functions.
  • Prelude: definitions loaded each time sapf starts. You can add your own; changes take effect the next time the app starts.
  • Documents you make with New Document.

Everything is saved as you type. If you change one of the built-in documents, Revert to Original puts it back. Log shows everything you’ve run.

Your documents, recordings and spectrograms are in the Files app, under On My iPhone (or iPad) › sapf.

Your documents, recordings and spectrograms are stored in this browser, on this device. Use the Download button when previewing a recording or spectrogram to keep a copy.

Plots, recordings and spectrograms

  • Plot Top of Stack (More menu, or Shift-⌘P) draws the signal on top of the stack in the Scope, so you can look at it without playing it.
  • record plays a sound and records it. When you stop it, the recording is saved in the Recordings folder and shown so you can listen to it: 440 0 sinosc .3 * "my-sound" record.
  • sgram draws a spectrogram of a finite signal, saves it in the Spectrograms folder and shows it. There is an example below.

Touch screens and keyboards

Touch screens

On a touch screen the editor starts out for reading, so tapping shows help without bringing up the keyboard. The bar under the editor has Run, Stop, Expand Selection, Plot and Find. 4. The language

The examples in this section print their results in the console. Comments after --> show what you should see. Most start with clear, which empties the stack, so you see only their own results.

The stack

Numbers go onto the stack. A word like + takes its arguments off the stack and puts its result back.

clear 2 3 +        ; --> 5
clear 2 3 4 * +    ; --> 14   (3 times 4, then plus 2)

There is no operator precedence: everything happens in the order written. A few words rearrange the stack: aa duplicates the top item, ba swaps the top two, clear removes everything, and cleard removes everything but the top.

clear 3 aa *   ; --> 9

Comments and parentheses

A semicolon starts a comment that runs to the end of the line. Parentheses group code to make it easier to read; they don’t change what it does.

clear (2 3 +) 4 *   ; --> 20

Numbers

Besides the usual 1, 2.5, .5 and 3.4e-3, numbers can have a suffix that scales them: k (×1000), M (×1,000,000), h (×100), c (×0.01), m (×0.001), u (×0.000001) and pi. A fraction with no spaces is a single number.

clear 1.5k 53m 5/4 2pi   ; --> 1500 0.053 1.25 6.28319

Words and variables

Everything that isn’t a number, string or bracket is a word. When a word runs, sapf looks up its value: a function is applied, and anything else is put on the stack. = before a word binds the value on top of the stack to it.

clear 5 = x   x x *   ; --> 25

Bind several values at once with parentheses, or take values out of a list with brackets:

clear 1 2 3 = (a b c)   c b a   ; --> 3 2 1
clear [4 5 6] = [d e f]   f e d   ; --> 6 5 4

Bindings can’t be changed, except at the top level, outside any brackets. Inside brackets, a binding lasts until the closing bracket.

Strings are written in double quotes: "hello".

Lists

Square brackets make a list. The code inside runs, and whatever it leaves on the stack becomes the list.

clear [1 2 + 3 4 *]   ; --> [3 12]

There are two kinds of list. A plain list, […], is a stream and can hold anything. A list written #[…] is a signal and holds only numbers; audio is made of signals.

Lists are lazy, so they can be infinite. ord is all the counting numbers, and N takes the first few items of a list.

clear ord 5 N        ; --> [1 2 3 4 5]
1 5 to               ; --> [1 2 3 4 5]

Functions

A backslash, argument names, and a body in brackets make a function. It isn’t run until it’s applied with !, or bound to a word and that word is used.

clear 3 4 \a b [a b + a b *] !   ; --> 7 12
clear \x [x x *] = square
7 square   ; --> 49

A string after the arguments is the function’s help, shown when you tapclick its name:

\a b "(a b --> sum product) the sum and product of a and b." [a b + a b *] = sumprod

The body runs on an empty stack: it sees only its arguments, not the rest of the caller’s stack.

Automatic mapping

Most functions that expect a single number apply themselves to each item when given a list instead.

clear [1 2 3] 10 *          ; --> [10 20 30]
[1 2 3] [10 20 30] +        ; --> [11 22 33]
[0 2] 4 to                  ; --> [[0 1 2 3 4] [2 3 4]]

This works over infinite lists too: ord 2 * is all the even numbers.

The each operator, @

@ after a value makes the next function apply to each of its items, rather than to the whole list.

clear [[1 2 3] [4 5 6]] reverse     ; --> [[4 5 6] [1 2 3]]
[[1 2 3] [4 5 6]] @ reverse         ; --> [[3 2 1] [6 5 4]]

Putting @ on one argument gives an outer product:

clear [1 2] @ [10 20] +   ; --> [[11 21] [12 22]]

@1 and @2 say which list is the outer loop, and @@ maps two levels deep.

Reducing and scanning

Put / after a two-argument math operator to combine a whole list, \ to keep the running results, and ^ to apply it to each neighbouring pair.

clear [1 2 3 4] +/       ; --> 10
[1 2 3 4] +\             ; --> [1 3 6 10]
[1 2 3 4 5 6] +^         ; --> [1 3 5 7 9 11]

Forms

A form is a set of named values, written in braces with each name after a colon. A comma before a name gets that value out of the form on the stack. A form can inherit from another by putting it first.

clear {:freq 440 :amp .2} = note
note ,freq   ; --> 440
{note :amp .5} = loud
loud ,freq loud ,amp   ; --> 440 0.5

Quoting

A mark before a word changes what happens to it:

`sinputs the function sin on the stack, without applying it
'sinputs the symbol sin on the stack
,namegets the value named name from the form on the stack
.namegets the value named name from the form on the stack and applies it
=namebinds the value on top of the stack to name

5. Making sound

Sounds play until you stop them, and each Run adds another. Stop each with the ■ Stop under its Run button, or everything with Stop in the toolbar.

Oscillators, filters and effects

Functions that make or process signals are called unit generators. Oscillators such as sinosc, saw and lfsaw take a frequency and a phase. Filters such as lpf (low pass) and rlpf (resonant low pass) take a signal and a cutoff frequency. Here, a sawtooth wave through a low pass filter whose cutoff is swept by another oscillator:

100 0 saw  .25 0 sinosc 1500 * 2000 +  .1 rlpf  .2 * play

Any argument can be a signal, which is how sounds change over time.

Stereo and multi-channel expansion

Give a unit generator a list, and it makes one for each item. Two items are left and right. These two sawtooth waves are 1 Hz apart, so they beat against each other:

[300 301] 0 saw .3 * play

A list of more than two channels is mixed down to stereo.

Rhythm and envelopes

impulse makes a click at a given rate, and decay turns each click into a fading envelope. Multiply a tone by the envelope for a repeating note:

4 0 impulse .2 decay  1000 0 sinosc *  .3 * play

Pitches and chords

nnhz converts MIDI note numbers to frequencies, and automatic mapping does the rest. +/ adds the three sine waves into one chord:

[60 64 67] nnhz 0 sinosc .1 * +/ play

Randomness

rand picks a random number between two values; given lists, it picks one for each pair. Run this a few times and each chord is different:

[48 55 60] [60 67 72] rand nnhz 0 sinosc .1 * +/ play

Looking at a sound

sgram draws a spectrogram of a finite signal and saves it as an image. N takes the first 48000 samples, one second at 48 kHz; 120 is the quietest level to show, in dB.

100 0 saw 48000 N 120 "saw" sgram

6. Getting help

  • TapClick any word in the editor to see its help.
  • List All Functions, also in the More menu, lists every built-in function and every one you’ve defined, with its help. You can search it.
  • In code, `sinosc help prints the help for one function (note the backquote), and helpall prints it all.

A function’s help starts with its arguments and results, like (freq phase --> out). Before that, unit generators and many other functions have a list of letters, one per argument, saying how it maps over lists:

za signal or a number. A stream (a plain list) here makes one of the function for each item.
ka single number. Any list here, signal or stream, makes one of the function for each item.
ataken as it is, with no mapping.

So sinosc, whose help begins @zz (freq phase --> out), takes signals for both its frequency and phase, and makes several oscillators when given a list.
